# Enterprise pilot acceptance and maintenance

**Not run in an Enterprise tenant.** Record evidence for the installed kit; do not copy consumer Gemini, Codex, local test or source-inspection results into the Enterprise pass column. Start only after the single-operator OAuth prerequisites in [README.md](README.md) are met. Use the explicitly authorized disposable organization and confirm its identity through the connected account.

Record: UTC time, kit manifest SHA-256/source version, Enterprise edition/app/region, operator, connector brand, action selection, prompt, actual tool name/result status, sanitized artifact hash, observed outcome and limitation. Keep credentials, signed URLs and contact rows out of general reports. For each check use PASS / FAIL / BLOCKED / NOT RUN and describe the evidence. Empty-data behavior does not certify populated metrics.

## Upgrade and rollback

1. Keep the currently installed ZIPs, manifest, administrator action selection and the exact maintainer revision used to build them. Hashes detect changes; they are not signatures or proof of trusted origin. Obtain the kit through the agreed trusted maintainer channel.
2. Generate a new kit from a verified release into a new directory, with the same builder and supporting documents retained. Use the maintainer verification command in `docs/PACKAGING.md` before handoff. Do not edit extracted files or ZIPs in place.
3. Compare changed skills, dependencies, action names and host limitations. Upload through a pilot skill owner's account first; keep sharing off. If the tenant offers no supported file-replacement action, turn off the previous skill before importing the replacement, and avoid leaving duplicate enabled versions. Record the resulting skill identities and file evidence.
4. Rerun affected checks in this document. Advance only capabilities actually demonstrated. Keep OAuth/account isolation failures blocking shared rollout.
5. To roll back, turn off the new skills and restore/re-enable the retained previous packages through the tenant's supported UI. Restore the prior action selection if it changed. No shared MCP redeploy or upstream repository rollback belongs to a skill-package rollback.
